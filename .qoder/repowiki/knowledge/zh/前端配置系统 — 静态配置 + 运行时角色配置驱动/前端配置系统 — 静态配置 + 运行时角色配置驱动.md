## 1. 系统概览

本应用采用**两层配置体系**：
- **静态编译期配置**：`config.js` 集中定义后端地址、协议、API 前缀与应用元信息，通过 ES Module `module.exports` 导出，被 `utils/request.js`、`store/modules/user.js`、`App.vue` 等模块直接 `import`。
- **运行时动态配置**：通过 `permission.js` 在应用启动时从后端 `/api/role-view-config/stuinfo`（或对应页面）拉取角色视图配置，缓存到 `uni.setStorageSync('roleConfig')`，并据此控制 TabBar、首页路由与功能开关；同时提供 `utils/roleViewConfig.js` 封装按页面维度加载、缓存与降级获取配置的逻辑。

两套配置共同决定应用的 API 基址、登录态、UI 布局与功能可见性。

## 2. 关键文件与职责

| 文件 | 职责 |
|---|---|
| `config.js` | 静态全局配置：`protocol/host/port/apiPrefix` 及派生 `baseUrl`，`appInfo`（名称、版本、Logo、协议链接） |
| `utils/request.js` | HTTP 请求封装，注入 `Authorization` 头、统一错误处理、401 自动重登与重试 |
| `store/modules/user.js` | Vuex 用户状态管理，基于 `config.baseUrl` 拼接头像 URL，持久化 token/roles/permissions 等 |
| `utils/storage.js` | 基于 `constant.js` 中 key 的本地存储封装，统一读写 `storage_data` 节点 |
| `utils/constant.js` | 本地存储键名常量（avatar/id/name/roles/permissions） |
| `permission.js` | 全局路由拦截器，初始化角色配置、白名单校验、未登录跳转、已登录访问登录页重定向至 homePage |
| `utils/roleViewConfig.js` | 按页面维度加载角色视图配置（含缓存、默认值降级） |
| `utils/roleConfig.js` / `utils/roleSystem.js` / `utils/roleViewConfig.js` | 角色相关工具：解析角色、系统级配置、视图配置 |
| `App.vue` | 应用入口，`onLaunch` 中注入 `globalData.config`，并按平台执行微信自动登录/H5 登录检查 |
| `main.js` | Vue 实例装配，注册 uView、plugins、权限拦截，挂载 store 与字典接口 |
| `test-config-driven.js` | 控制台测试脚本，验证 baseUrl、角色配置加载、缓存与降级机制 |

## 3. 架构与约定

### 3.1 静态配置层
- 单一来源：所有环境差异仅体现在 `config.js` 的 `host/port/apiPrefix`，部署 HTTPS 时改 `protocol` 即可。
- 派生属性：`config.baseUrl` 通过 getter 自动拼接，避免各处重复拼接。
- 应用信息：`appInfo` 暴露给 UI 展示 Logo、版本、协议链接。

### 3.2 运行时配置层
- 初始化时机：`App.vue.onLaunch` → `initRoleConfig()`（`permission.js`）→ 调用 `getRoleConfig()` 拉取后端角色视图配置。
- 缓存策略：成功响应写入 `uni.setStorageSync('roleConfig', data)` 与 `userRoles`，后续同步读取 `getRoleConfigSync()` 优先使用内存 `globalRoleConfig`，否则回退到 storage。
- 降级策略：网络异常或返回非 200 时使用内置默认配置（教师角色、默认 homePage、空 tabBar）。
- 功能开关：`hasFeature(feature)` 读取 `config.features[feature] === true` 判断是否启用某特性。

### 3.3 配置消费方式
- **HTTP 基址**：`utils/request.js` 与 `store/modules/user.js` 均 `import config from '@/config'` 并使用 `config.baseUrl`。
- **全局对象**：`App.vue.initConfig()` 将 `config` 挂到 `this.globalData.config`，组件可通过 `getApp().globalData.config` 访问。
- **路由与导航**：`permission.js` 根据 `homePage` 字段重定向已登录用户访问登录页的场景。
- **TabBar 动态化**：小程序环境下通过 `uni.setTabBar({ list })` 动态设置底部导航。

## 4. 开发者规范

1. **新增静态配置项**：仅在 `config.js` 中添加，并通过 getter 或新字段暴露，禁止在业务文件中硬编码 host/port。
2. **修改后端地址**：只改 `config.js` 的 `protocol/host/port/apiPrefix`，确保 `config.baseUrl` 正确拼接。
3. **新增运行时配置**：
   - 在后端 `/api/role-view-config/{page}` 返回配置数据；
   - 如需页面级配置，使用 `utils/roleViewConfig.js` 的 `getRoleViewConfig(pageKey)` 加载，利用其缓存与降级能力；
   - 若需全局功能开关，在返回数据的 `features` 字段中声明，并通过 `hasFeature(key)` 判断。
4. **本地存储键名**：统一使用 `utils/constant.js` 中定义的 key，通过 `utils/storage.js` 的 `set/get/remove/clean` 操作，避免散落的字符串键。
5. **Token 与鉴权**：所有需要认证的请求由 `utils/request.js` 自动注入 `Authorization: Bearer <token>`；401 场景下微信端触发 `WxLogin` 并重试，H5 端直接跳转登录页。
6. **路由拦截**：新增页面路径应评估是否需要加入 `whiteList`，或在 `permission.js` 中补充特殊处理逻辑。
7. **配置变更热更新**：重启应用后 `initRoleConfig` 会重新拉取最新配置；如需立即生效可调用 `clearConfigCache()`（见测试脚本）后再次加载。
